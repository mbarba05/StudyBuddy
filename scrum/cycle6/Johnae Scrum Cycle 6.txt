Scrum Cycle 6:
        During this cycle, I focused on building and fixing the in-app notification system for matchmaking features in the app. I implemented a notification provider using React Context that listens to Supabase realtime events for both friend requests and friend acceptance, and displays a banner-style notification similar to Instagram. 
I also had to go back and forth between different articles and documentation because of changes in the newer Expo SDK. Push notifications no longer worked the same way, which affected my previous implementation from Scrum cycles 4 and 5 since I originally used Expo’s notification system. Because of this, I had to revisit and adjust my code to make sure notifications still worked properly within the app. Instead of relying on push notifications, I shifted to using in-app notifications with Supabase realtime listeners. I also made sure that the  notification listener was placed at the root level of the app so it could run globally and consistently detect events no matter which screen the user is on.
I added features such as automatic dismissal of notifications after a few seconds, handling multiple notifications using a queue system, and preventing duplicate notifications. I also ensured proper cleanup of Supabase channels when the component unmounts to avoid memory issues. In addition to development, I created both coding and manual test cases. I used Jest to simulate realtime events and verify that notifications display correctly, disappear after the timer, and clean up properly. I also manually tested the feature using Expo Go on my phone to confirm that the UI behaves correctly and navigation works when interacting with notifications.
