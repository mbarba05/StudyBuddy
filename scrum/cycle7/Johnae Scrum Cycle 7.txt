In this cycle, I had to go back and forth between different articles and documentation because of changes in the newer Expo SDK. Push notifications no longer worked the same way, which affected my previous implementation from Scrum cycles 5 and 6 since I originally used Expo’s notification system. Because of this, I had to revisit and adjust my code to make sure notifications still worked properly. The issue mainly affected my push notifications, not really my in-app notifications, so I had to move away from relying on Expo’s push system. I ended up switching to using Supabase, Edge Functions, and Native Notify instead. While doing this, I also had to fix issues like incorrect column names in my database, push tokens not saving at first, and some network request errors. I added debug logs to figure out what was going wrong and eventually confirmed that the push token was being generated and stored correctly.
We would’ve been able to bypass a lot of these issues if someone in the group had an Apple Developer account, but since it costs about $100 a year, none of us had one. Because of that, I had to focus more on fixing and testing the backend instead of actually seeing the notifications on a physical iPhone. The code I followed was based on updated documentation, so I had to go back and adjust what I already did in the previous cycle and remove older functions that were causing conflicts. Even though I couldn’t fully test the notifications on my own device, I was still able to confirm that everything works through the logs, Supabase updates, and successful Edge Function responses. Overall, this cycle helped me understand more about how push notifications work and how to debug issues when things break due to updates.
